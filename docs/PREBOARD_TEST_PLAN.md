## P1-1 控制周期实测（固定 500ms 是否成立）

**为什么**：PID 内部按 `Ts=0.5s` 计算，若实际周期抖动大，积分/微分等效增益会漂移。

**方法 A（推荐，最直观）**：临时把空闲引脚 PB1 配成推挽输出，在 `Control_Tick()` 调用前后翻转：

```c
/* 临时调试片段，测完删除，不要提交 */
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_1);   /* 进入 Control_Tick 前 */
Control_Tick();
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_1);   /* 返回后 */
```
示波器测：一个完整周期的高/低电平时长即 Control_Tick 执行时间，翻转间隔即调度周期。

**方法 B（无示波器）**：用 DWT 周期计数器统计（72MHz，1 计数 ≈ 13.9ns）：

```c
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CYCCNT = 0;
DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
/* 在 Control_Tick 前后各读一次 DWT->CYCCNT，差值/72 得微秒 */
```
把最近 N 次的 min/max/avg 打到串口或 OLED 第 4 行。

**判据**：
- 调度周期 500ms ± 20ms（±4%）→ 可直接沿用固定 `Ts`；
- 抖动 > 50ms（±10%）→ 再考虑传入实测 dt（**此项需你确认后才改代码**）。

## P1-2 OLED 整屏刷新耗时

**为什么**：软件 I²C 8×16 字体整屏约 4×16=64 字符 ≈ 1024 字节数据，每字节 9 个时钟 + 起停开销，可能吃掉几毫秒到几十毫秒 CPU。

**方法**：DWT 计数包住 `Menu_Render()`，记录一次完整刷新耗时。

**判据**：
- < 20ms（占 500ms 周期 4%）→ 可接受，无需改动；
- 20~50ms → 观察按键响应（10ms 时间片是否被明显推迟）；
- \> 50ms → 优先考虑：只刷变化字段、提高 I²C 位速（软件 I²C 可通过减小延时）、或切硬件 I2C1。

## P1-3 UART 阻塞发送与丢包

**为什么**：`Usart_Send` 阻塞最长 100ms（HAL 超时），Flash 擦写期间关中断 20~40ms，都可能丢接收字节。

**方法**：
1. 上位机 `python host/monitor_cli.py --port COMx` 连续跑 **30 分钟**；
2. 期间每 5 秒下发一次 `SET_TARGET`（可用 GUI 或脚本），并每 30 秒执行一次"保存到 Flash"（触发关中断擦写）；
3. 记录：`crc_err` 计数、ACK 丢失次数、`frames_ok` 累计。

**判据**：
- 无 CRC 错误、无 ACK 超时（手动断开除外）→ 当前阻塞实现可接受，暂不改 DMA；
- 出现 CRC 错误或 ACK 丢失 → 优先把发送改非阻塞（队列 + `HAL_UART_Transmit_IT`），**此项需你确认后才改**。

## P1-4 NTC 原始噪声与滤波效果

**为什么**：噪声直接进 PID 微分项，放大成占空比抖动，也会让 OLED 数字跳。

**方法**：
1. 临时把 `sensor.c` 的 8 次平均改为输出**单次原始值**（或在 `Sensor_Read` 里加一个 raw 输出通道）；
2. 室温静止采集 100 个点，记录 ADC 原始值 min/max；换算成温度：
   灵敏度推导：`dV/dT = Vcc·Rf/(Rf+R)² · dR/dT`，其中 `dR/dT = −B·R/T²`
   - 25℃（R=10kΩ、Rf=10kΩ、Vcc=3.3V）：`dV/dT ≈ −36.7 mV/℃`
   - 1 LSB = 3.3V/4095 = **0.806 mV** → 25℃ 下 **≈ 0.022 ℃/LSB**（不是 0.06，早期算错）
   - 全温区（同一分压）：15℃ 0.0216 / 25℃ 0.0220 / 35℃ 0.0246 / 45℃ 0.0296 / 60℃ 0.0430 ℃/LSB
     → 温度越高 NTC 阻值越低、分压灵敏度越差，**60℃ 附近分辨率约为 25℃ 的 1/2**
   - 8 次算术平均只压随机噪声（噪声降为 1/√8 ≈ 35%），**不改善量化误差**；
   - **以上仅为理论估算**：实际灵敏度还受参考电压（3.3V 实际偏差）、分压电阻容差（1% → 约 0.02℃ 量级）、
     NTC 的 B 值误差、走线与 ADC 非线性影响。**必须用实测 ADC 值与参考温度计做两点校准**（如 0℃ 冰水 + 室温），
     再据此确认每 LSB 对应的实际温度，而不是直接采用理论值；
3. 再恢复 8 次平均，重采 100 点对比。

**判据**：
- 滤波后峰峰 < 0.3℃（25℃ 下约等于 14 LSB）→ 保持现状；
- 0.3~1℃ → 考虑"中值 + 滑动平均"（需改代码，先记录数据再决定）；
- \> 1℃ → 先查布线（NTC 长线、共地质量、负载电源噪声），不要急着加滤波。

## P1-5 真实 PID 参数整定（**禁止无人值守**）

**为什么**：`Kp=8 / Ki=0.10 / Kd=1.5` 只对软件一阶惯性模型有效，真实环境箱热惯性完全不同。

**方法**（保守起步，逐步逼近）：
1. 起点：`Kp=4.0 / Ki=0.05 / Kd=0`（菜单 KEY2 选 KP/KI/KD，KEY3 步进）；
2. 设定目标比环境高 10℃（如 25→35℃），记录升温曲线（`monitor_cli` 日志或 GUI 截图）；
3. 只调 Kp：加大到出现轻微超调后退回一档；
4. 加 Ki 消除稳态误差（每次加倍，观察是否开始振荡）；
5. 最后加 Kd 抑制超调（从小值开始，噪声大就不加）。
6. 换目标 15℃ 温差重复验证一次。

**判据**：超调 < 2℃、稳态误差 < 0.5℃、无持续振荡。记录最终参数到 `docs/TEST_REPORT.md`。

## P1-6 Python GUI 实际启动

**为什么**：`py_compile` 只证明语法正确，不证明界面能跑。

## P1-7 故障确认与恢复完整路径（**安全关键**）

按顺序执行并逐步记录：

| 步骤 | 操作 | 期望 | 记录 |
|------|------|------|------|
| 1 | 正常闭环运行中，拔掉 NTC | 立即 `FLT`、PWM=0、风扇 ON | |
| 2 | 按 KEY1 确认故障 | 显示 `SENSOR STILL ERR`，仍 `FLT`（**不能**回 STB） | |
| 3 | 串口发 ACK_FAULT | 回 ACK 码 **6**（sensor invalid），状态仍 FLT | |
| 4 | 插回 NTC，等 1 个控制周期 | 仍 `FLT`（不自动恢复，符合设计） | |
| 5 | 再按 KEY1 | 回 `STB`，PWM=0、风扇 OFF | |
| 6 | 按 KEY1 启动 | `RUN`，闭环恢复，无积分突变 | |
| 7 | 断电重启 | 参数从 Flash 恢复；状态 `STB`（不自动启动） | |

**判据**：7 步全部符合期望；任何一步出现"自动恢复运行"或"带着无效传感器进 RUN"，即视为**安全缺陷**，立即停止测试并反馈。

## P1-8 NTC 断线后的实际关断延迟（上板前先算，实测待上板）

**静态分析（已完成的推理，不是实测）**

| 环节 | 时延 |
|------|------|
| 断线发生 → 下一次 `Sensor_Read()` | 0 ~ 500ms（取决于断在采样周期哪个时刻） |
| 8 次 ADC 采样（55.5 周期/次 @12MHz） | ≈ 50µs（可忽略） |
| 判定 `is_valid=0` → `safety_interlock()` 关断 | **同一 tick 内**（联锁在 PID 之前） |
| `Heater_Off()` → CCR=0 生效 | 1 个 PWM 周期内（1ms） |
| 主循环最坏阻塞（UART 发送 100ms / Flash 擦写 40ms / OLED 刷新） | ≤ 140ms，可能推迟一次采样 |

→ **延迟上界 ≈ 0.65s（典型 0~0.5s）**。若断线形式是"线间短路到中间阻值"，则走换算超范围判无效，同样在一个 tick 内关断。

**实测方法**：PA8 接 LED 假负载闭环运行；拔线瞬间用示波器单次触发（或在进入 FAULT 时翻转 PB1 作为标记），测"断线 → PA8 变低"时间差，重复 5 次取最大。
**判据**：≤ 0.7s 合格；> 1s 视为缺陷。

## P1-9 IWDG 复位与 PA8 关断行为（上板前先算，实测待上板）

**静态分析**

| 失效形态 | 谁兜底 | 最坏加热时长 |
|----------|--------|--------------|
| NMI / HardFault / MemManage / BusFault / UsageFault（五个异常统一） | `fatal_stop()` → `Heater_PanicOff()`：MOE=0 + 停计数 + **PA8 切回 GPIO 推挽** + 拉低 + 开风扇 | **设计目标 µs 级（待示波器实测）**；注意仅写 BRR 无效，必须切模式 |
| 主循环死循环、卡在 while(1)（未进异常） | IWDG：`64×625/LSI` = 0.67s（LSI 60kHz）~ **1.33s（LSI 30kHz）** | ≈1.33s |
| 复位之后 | PA8 回到上电默认（浮空输入）+ 板上 10k 下拉 → 栅极 <0.1V → MOS 关断 | 0 |

**已知残余风险**：IWDG 窗口内（最多 1.33s）加热器仍按最后一次占空比输出。彻底消除需要独立温控开关串联加热回路（`WIRING.md` §0 待回填项），当前**未安装**。

**实测方法**：① 暂在 `while(1)` 前加死循环（或用调试器暂停 CPU 不喂狗），示波器测 PA8 从停止喂狗到被拉低的时长；② 复位后立即测 PA8 应为 0V；③ 观察 OLED 第 4 行是否出现 `WDG` 标志（`IWDG_ResetWasWatchdog()`）。
**判据**：≤ 1.5s 内复位；复位后 PA8 = 0；`WDG` 标志正确显示。

**波形三点必须都抓**（对应评审要求）：
1. 正常 PWM：1kHz、占空比与 OLED 显示一致；
2. 故障处理瞬间：从触发异常/拔线到 PA8 下降沿的时间（预期 µs~ms 级，拔线场景 ≤0.7s）；
3. 复位后：PA8 保持 0V，直到再次进入 RUNNING。

## P1-10 软件输出许可的生效性（示波器实测）

**为什么**：`s_hw_en` 只是内存变量，论文式地"关闭"不等于引脚真的为低。必须实测确认写 0 后 PA8 立刻变低。

**方法**：
1. 编译 `SENSOR_SIM_ENABLE=1`，进 RUNNING，让 PID 输出非零占空比（OLED 上 `H%` 明显 > 0）；
2. 示波器接 PA8（假负载），观察是否**始终为低**（此时逻辑占空比只影响仿真温度）；
3. 再切回 `SENSOR_SIM_ENABLE=0` + 真实 NTC，在 RUNNING 下确认 PA8 出现 1kHz PWM；
4. 触发一次 FAULT（拔 NTC），确认 PA8 在一个控制周期内变低。

**判据**：SIM 模式下 PA8 全程 0V；REAL 模式有 1kHz 波形；FAULT 后 ≤0.7s 变低。
**注意**：本项只证明"软件写入生效"，**不证明物理断电**；物理断电依赖栅极下拉、串联温控开关等器件（见 `ARCHITECTURE.md` §2）。

## 与代码改动的关系

本计划**默认不改代码**。只有在以下条件同时满足时才动代码：
1. 已拿到实测数据；
2. 数据确实超出判据；
3. 你明确同意改动范围。

优先级建议：P1-1 → P1-2 → P1-7（安全路径）→ P1-3 → P1-4 → P1-5 → P1-6。
