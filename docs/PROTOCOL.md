# 通信协议规范（PROTOCOL v1）

> 物理层：USART1（PA9/PA10），**115200 8N1**，无流控。
> 角色：PC（上位机）主动下发命令；MCU 应答 + 每 200ms 主动上报状态。
> 实现对照：固件 `App/Src/comm.c` ↔ 上位机 `host/protocol.py`（两侧 CRC/字段顺序完全一致）。

---

## 1. 帧格式

```
┌──────┬──────┬─────┬─────┬───────────────┬────────┬────────┐
│ 0xAA │ 0x55 │ CMD │ LEN │ PAYLOAD[LEN]  │ CRC_L  │ CRC_H  │
└──────┴──────┴─────┴─────┴───────────────┴────────┴────────┘
   帧头(2B)      1B    1B      0~32B          16bit 小端
```

| 项 | 规定 |
|----|------|
| 帧头 | 固定 `AA 55` |
| CMD | 命令字，见 §2；响应帧 = 命令字 `\| 0x80` |
| LEN | 载荷字节数，**最大 32**，超限整帧丢弃并回 NACK(2) |
| 校验 | **CRC-16/CCITT-FALSE**：poly `0x1021`、init `0xFFFF`、不反射、无 xorout |
| 校验范围 | `CMD` + `LEN` + `PAYLOAD`（不含帧头） |
| 字节序 | 多字节数值一律**小端**（float 按 IEEE-754 单精度） |
| 帧总长 | `6 + LEN` 字节 |
| 应答超时（上位机） | 建议 300ms，超时重发，连续 3 次判链路故障 |

已知限制：载荷/CRC 中出现 `AA 55` 且前一帧被截断时，最坏情况丢弃当前帧，下一帧自动恢复（解析器逐字节重同步，已在 T6 测试覆盖）。

## 2. 命令字

| CMD | 名称 | 请求载荷 | 响应 | 响应载荷 |
|-----|------|----------|------|----------|
| 0x01 | GET_STATUS | 无 | 0x81 | 状态帧 25B（§3） |
| 0x02 | SET_TARGET | f32 目标温度 | 0x82 | u8 状态码 |
| 0x03 | START | 无 | 0x83 | u8 状态码 |
| 0x04 | STOP | 无 | 0x84 | u8 状态码 |
| 0x05 | ACK_FAULT | 无 | 0x85 | u8 状态码 |
| 0x06 | SET_PID | f32 kp + f32 ki + f32 kd | 0x86 | u8 状态码 |
| 0x07 | SAVE_PARAMS | 无 | 0x87 | u8 状态码（**仅 STANDBY 允许**；RUNNING/FAULT 返回 4） |
| 0x08 | GET_PARAMS | 无 | 0x88 | f32 target + kp + ki + kd（16B） |
| 0x09 | GET_DIAG | 无 | 0x89 | 诊断帧 8B（§3.1） |
| 0x7F | NACK | u8 错误码 | — | 由下位机主动发出 |

### 状态码

| 码 | 含义 | 触发场景 |
|----|------|----------|
| 0 | OK | 执行成功 |
| 1 | CRC 错误 | 校验不符，帧被丢弃（NACK 携带） |
| 2 | 长度/协议错误 | LEN 超 32、载荷长度与命令不匹配、未知命令 |
| 3 | 参数越界 | 目标不在 0~70℃；kp∉[0,50]、ki∉[0,5]、kd∉[0,20]；参数为 NaN/Inf |
| 4 | 状态不允许 | 非 STANDBY 时 START、非 RUNNING 时 STOP |
| 5 | Flash 保存失败 | 擦除/写入/回读校验失败（第二轮审查新增） |
| 6 | 传感器无效 | START 时传感器读数无效；或 FAULT 确认时传感器仍无效（新增） |

> 安全语义：**故障只能通过 ACK_FAULT 解除**，且解除后回到 STANDBY，不会自动恢复闭环。
> `START` 与 `ACK_FAULT` 在固件内部都会做一次**新鲜传感器读数校验**，非法时分别回 6，
> 上位机不能通过任何命令绕过该检查。

## 3. 状态帧载荷（25 字节）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | f32 | temp | 当前温度 ℃；**无效时为 -999.0**（哨兵值） |
| 4 | f32 | target | 当前目标温度 ℃ |
| 8 | u8 | duty | 加热占空比 0~100 |
| 9 | u8 | fan | 0=关 1=开 |
| 10 | u8 | state | 0=INI 1=STB 2=RUN 3=FLT |
| 11 | u8 | sim | **1=SIM 模拟数据源，0=REAL 真实传感器** |
| 12 | u8 | fault | 0=无 1=传感器故障 2=超温 3=热失控（高功率输出但温度不涨：传感器脱落/加热回路异常） |
| 13 | f32 | kp | 当前 Kp |
| 17 | f32 | ki | 当前 Ki |
| 21 | f32 | kd | 当前 Kd |

Python 结构：`struct.Struct("<ffBBBBBfff")`（`host/protocol.py: STATUS_STRUCT`）。

### 3.1 诊断帧载荷（8 字节，`GET_DIAG` 的响应）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | u32 | overflow | 环形缓冲**溢出丢弃**的字节数（累计，`Usart_StartRx` 清零） |
| 4 | u32 | rx_bytes | **成功入环**的字节数（累计，`Usart_StartRx` 清零） |

Python 结构：`struct.Struct("<II")`。

怎么用这两个数：

- `overflow` 一直是 0 → 主机的发送速率没超过消化上限，链路干净。
- `overflow` 在增长 → 主机发送速率超过了 **128 B/10ms ≈ 12.8KB/s** 的消化上限（高于 115200 的 11.5KB/s 才有余量），此时出现的"命令无应答"可以确定是**链路丢字节**，而不是设备没执行。
- `rx_bytes` 与主机实际发送字节数对不上（少），说明字节在**进缓冲之前**就丢了（线路/波特率/接线），与缓冲无关。

> 这条命令是纯增量：25 字节状态帧和其余命令的格式都没动。

## 4. 示例帧（实测生成的十六进制）

| 操作 | 帧字节 | 长度 |
|------|--------|------|
| GET_STATUS | `AA 55 01 00 3E 2E` | 6 |
| START | `AA 55 03 00 5C 48` | 6 |
| SET_TARGET 45.0℃ | `AA 55 02 04 00 00 34 42 81 AD` | 10 |
| SET_PID 8.0 / 0.1 / 1.5 | `AA 55 06 0C 00 00 00 41 CD CC CC 3D 00 00 C0 3F E4 28` | 18 |
| 应答（例：SET_TARGET 成功） | `AA 55 82 01 00 xx xx` | 7 |

> `45.0f` = `0x42340000` → 小端 `00 00 34 42`；`8.0f` = `0x41000000` → `00 00 00 41`。

## 5. 上位机使用

### GUI（推荐）
```bash
pip install pyserial            # tkinter 为标准库（嵌入式 Python 发行版可能不含）
python host/app_gui.py
```
操作顺序：选串口 → 连接 → 观察曲线与徽标（RUN/STB/FLT、SIM/REAL、FAULT 原因）→ 调参下发 → 保存到 Flash。

### 终端监控（无 GUI 环境）
```bash
python host/monitor_cli.py --port COM5              # 实时表格
python host/monitor_cli.py --port COM5 --cmd target=48.0
python host/monitor_cli.py --demo                    # 无硬件跑通解析链路
```

### 协议自动化测试
```bash
python host/test_protocol.py     # 46 项检查，含 CRC/分片/坏帧/越界/模糊测试
```

## 6. 扩展约定

- 新增命令：`0x09` 起递增，响应固定 `|0x80`，LEN 上限仍为 32
- 新增状态字段：只能**追加在 25 字节之后**并升级协议版本（避免上位机错位解析）
- 参数镜像升级：`param_codec.h` 的 `APP_PARAM_VERSION` 递增，旧数据校验失败自动回默认值（不会误用脏参数）
