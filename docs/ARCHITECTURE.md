# 系统架构说明（ARCHITECTURE）

> 项目：基于 STM32 的智能温控与故障监测终端
> 平台：STM32F103C8T6（64KB Flash / 20KB RAM）· HAL（FW_F1 V1.8.7）· Keil5

---

## 1. 总体架构

```
┌──────────────────────────── 上位机（PC / Python） ────────────────────────────┐
│  app_gui.py（tkinter 实时曲线 + 调参面板）   monitor_cli.py（终端监视）        │
│  protocol.py（帧编解码 / CRC16 / 越界校验，与固件严格对应）                     │
└───────────────────────────────────┬──────────────────────────────────────────┘
                                    │ USB-TTL 115200 8N1（AA 55 ... CRC16）
┌───────────────────────────────────▼──────────────────────────────────────────┐
│                            STM32F103C8T6 固件                                  │
│                                                                               │
│  ┌── 应用层 App/ ──────────────────────────────────────────────────────────┐  │
│  │  control.c   四状态机 + 安全联锁 + 风扇迟滞（500ms 周期）                │  │
│  │  menu.c      按键菜单：启停/设温/改 PID/保存                             │  │

│  │  param_codec.c  镜像序列化 / CRC32（纯 C，可宿主机测试）                 │  │
│  │  pid.c       位置式 PID（纯 C，零 HAL 依赖）                             │  │
│  └───────────────────────────────┬─────────────────────────────────────────┘  │
│                                  │ 只调 Hardware 接口，不碰寄存器              │
│  ┌── 硬件抽象层 Hardware/ ───────▼─────────────────────────────────────────┐  │
│  │  sensor.c  NTC(ADC1_IN0) + 一阶惯性模拟双底层，统一 Sensor_Read()        │  │
│  │  heater.c  TIM1_CH1 1kHz PWM，占空比 0~100                                │  │

│  │  key.c     PB12/13/14 状态机消抖（10ms 节拍，无 Delay）                   │  │
│  │  oled.c    SSD1306 软件 I2C（PB6/PB7）                                    │  │
│  └───────────────────────────────┬─────────────────────────────────────────┘  │
│                                  │ HAL API                                    │
│  ┌── 外设层 Core/ ───────────────▼─────────────────────────────────────────┐  │
│  │  adc.c · tim.c · usart.c · gpio.c · iwdg.c · stm32f1xx_hal_msp.c · it.c   │  │
│  └─────────────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────────────┘
        │                    │                    │                  │
   PA8 → MOSFET → 加热器   PB0 → MOSFET → 风扇  ADC1_IN0 ← NTC分压  PA9/PA10 USB-TTL
```

依赖方向严格单向：`main → App → Hardware → HAL`。`pid.c` 与 `param_codec.c` 不依赖任何一层，因此可在 PC 上直接编译测试。

## 2. 术语约定（全项目统一用词）

第二轮审查后发现"闸门"一词容易被误读成"硬件保护"，这里固定四个层次，文档与代码注释一律照此表述：

| 术语 | 英文/符号 | 本质 | 能防住什么 | **不能**防什么 |
|------|-----------|------|------------|----------------|
| **软件输出许可**（闸门） | software output permission，`Heater_EnableOutput()` / `s_hw_en` | 一个**内存变量**，决定逻辑占空比是否落到 CCR | 上层逻辑错误、模拟数据误驱动、状态机异常 | CPU 跑飞、HardFault 死循环（此时变量还在，TIM1 继续输出） |
| **软件联锁** | software interlock | 控制周期内的判断（`is_valid==0` / >75℃ / PID 异常） | 传感器失效、超温、参数异常 | 主循环停摆时不再执行 |
| **无源硬件保护** | passive hardware protection | 不依赖固件与时钟的物理器件：栅极 10k 下拉、KSD9700 常闭温控开关串联加热回路 | 复位/掉电/引脚浮空时默认关断；器件级超温断流 | 需要选型与安装（当前未装温控开关） |
| **独立硬件复位** | IWDG | LSI 独立时钟的看门狗，超时强制复位 | CPU 挂死时把 PA8 拉回上电默认（浮空+下拉=关断） | 复位窗口内（0.67~1.33s）加热仍按最后占空比输出 |

> 本文与代码中出现的"闸门/总闸"**一律指"软件输出许可"**，不是硬件保护。
> 符号名 `Heater_EnableOutput` 保留不改（避免无谓的接口变更），语义按上表。

### 2.1 致命异常关断序列（`Heater_PanicOff()`）

第三轮审查发现：**PA8 处于 AF 模式时，写 `GPIOA->BRR` 不会改变引脚电平**——引脚由 TIM1_CH1 驱动，
GPIO 输出寄存器被旁路；且 `MOE=0` 后引脚状态还受 `BDTR.OSSI` / `CR2.OIS1` 影响（本工程未配 OSSI）。
因此不能靠"MOE=0 + 写 BRR"宣称已关断。

实际序列（`Hardware/heater.c`，裸寄存器、不调 HAL）：

| 步 | 操作 | 目的 |
|----|------|------|
| 0 | `RCC->APB2ENR |= IOPAEN\|IOPBEN` | 保证 GPIO 时钟开启（否则后续写寄存器被忽略） |
| 1 | `TIM1->CR2 &= ~OIS1` | 把通道空闲电平预先定为低，不依赖 `BDTR.OSSI` 的复位默认值 |
| 2 | `TIM1->BDTR &= ~MOE` | 关闭高级定时器主输出 |
| 3 | `TIM1->CR1 &= ~CEN` | 停计数器，避免残余比较事件再次驱动输出 |
| 4 | `GPIOA->BRR = HEATER_Pin` | **先清 ODR 锁存**（AF 模式下不影响引脚，只为下一步准备） |
| 5 | `GPIOA->CRH = (CRH & ~0xF) \| 0x2` | PA8 切回通用推挽输出；因 ODR 已为 0，**切换瞬间即为低，无高电平毛刺** |
| 6 | `GPIOB->BSRR = FAN_Pin` | 开风扇散热（若未配置为输出则无效果，可接受降级） |
| 7 | `__DSB()` | 确保写操作落地再进入死循环 |

> 第 4 与第 5 步的先后顺序是本次微调的重点：若先切模式再清 ODR，而 ODR 残留为 1，
> 切换瞬间会输出一个约几十 ns 的高电平毛刺（对栅极驱动虽通常无害，但没有理由留下）。

**统一入口**：`NMI / HardFault / MemManage / BusFault / UsageFault` 五个异常全部调用同一函数
（`stm32f1xx_it.c` 的 `fatal_stop()`），`Error_Handler()` 也调用它——不再出现"部分路径关、部分路径不关"。

**仍有的残余风险**：若 CPU 在关断代码执行前就被复位打断，或异常本身发生在关断指令流中，
IWDG 复位窗口（0.67~1.33s）内负载仍按最后占空比工作。**真实加热器必须具备独立串联过温保护。**

## 3. 时间片调度（非阻塞，全部基于 `HAL_GetTick()`）

| 周期 | 任务 | 说明 |
|------|------|------|
| 每轮循环 | `IWDG_Feed()` | 喂独立看门狗（标称 1.0s 超时，CPU 卡死则硬件复位关断 PA8） |
| 10 ms | `Key_Scan()` | 3 键并行状态机消抖（20ms 判定、1s 长按） |
| 10 ms | `Menu_Tick()` | 消费按键事件，调控制接口 |
| 10 ms | `Comm_Tick()` | 最多消化 64 字节；每 200ms 主动上报状态帧 |
| 500 ms | `Control_Tick()` | 读传感器 → 联锁 → PID → 风扇迟滞 |
| 500 ms | `Menu_Render()` | OLED 整屏刷新（4 行 16 列） |
| 1000 ms | 秒计数 | 仅用于显示运行时长 |

全工程主循环无 `HAL_Delay`；唯一阻塞点是 OLED 初始化延时（100ms）与 UART 单帧发送（≤3.5ms）。

## 4. 控制数据流

```
        ┌──────────────┐
        │ Sensor_Read()│ ── 10ms? 否：500ms 调用一次
        └──────┬───────┘
               │ Sensor_Data_t {temp, humidity, is_simulated, is_valid}
               ▼
    ┌──────────────────────┐   无效/超 75℃   ┌───────────────────────┐
    │ safety_interlock()   │ ──────────────> │ FAULT：加热 0%，风扇 ON │
    │ 每 tick 最先执行      │                 │ 仅人工确认可解除        │
    └──────┬───────────────┘                 └───────────────────────┘
           │ 正常
           ▼
    ┌──────────────────────┐   duty(0~100)
    │ pid_update(sp, temp) │ ─────────────> Heater_SetDuty() → TIM1 CCR1
    └──────┬───────────────┘
           │ temp 与 target 比较（迟滞）
           ▼
    Fan_On() / Fan_Off()   （> target+2.0℃ 开，< target+0.5℃ 关）
```

状态机：

```
  INIT ──自检通过──> STANDBY ──Control_Start()──> RUNNING
    │                  ▲   │                        │
    │ 传感器无效        │   └────Control_Stop()──────┘
    └──────────────────┼──> FAULT（锁定）
                       └── Control_AckFault()
```

## 5. 关键设计决策

| 决策 | 原因 | 代价 |
|------|------|------|
| PID 纯 C 无 HAL | 可在 PC 上跑真实单测（本项目 20 项用例全过），换 MCU 不用改 | 需要自己传 dt、自己做限幅 |
| 传感器双底层 + `is_simulated` 标志 | 无硬件也能验证完整闭环；SIM/REAL 在 OLED 与上位机双处显式标注，不伪装 | 显示与通信层都要透传该标志 |
| **模拟模式为编译期开关**（`SENSOR_SIM_ENABLE`，默认 0） | 运行时自动回退会让"没接传感器"变成"用假温度加热真实负载"，属致命失效；改成编译期选择后，出厂固件根本不含模拟路径 | 台架验证需重新编译一次 |
| **加热器软件输出许可（闸门）**（`Heater_EnableOutput`） | 安全不能只靠调用者自觉：许可关闭时任何 SetDuty 都只更新逻辑值，PA8 恒低；但它是软件变量，**不防 CPU 跑飞**（见 §2 术语表） | 多一个状态变量，需在每个状态出口保持一致 |
| OLED 用软件 I2C（PB6/PB7） | 复用课程里已验证的驱动；不与任何外设抢时序；NTC 方案无需 I2C 外设 | CPU 占用略高（单帧刷新 ~10ms，500ms 一次可忽略） |
| 参数存末页 Flash（0x0800FC00） | C8T6 无 EEPROM；末页不与代码冲突（当前 Code 17KB / 64KB） | 写入需整页擦除，寿命 ~10k 次，所以只在用户显式保存时写 |
| 状态帧 200ms 主动上报 | 上位机无需轮询即可绘图，协议更简单 | 占用约 2.5KB/s 带宽，115200 下充裕 |
| 联锁放在 PID 之前 | 安全优先于控制，任何异常都不允许进入 PID 计算 | 故障时 PID 状态被冻结（下次启动会 reset） |
