# 系统架构说明（ARCHITECTURE）

> 项目：基于 STM32 的智能温控与故障监测终端
> 平台：STM32F103C8T6（64KB Flash / 20KB RAM）· HAL（FW_F1 V1.8.7）· Keil5

---

## 1. 总体架构

```
┌──────────────────────────── 上位机（PC / Python） ────────────────────────────┐
│  app_gui.py（tkinter 实时曲线 + 调参面板）   monitor_cli.py（终端监视）        │
│  protocol.py（帧编解码 / CRC16 / 越界校验，与固件严格对应）                     │
└───────────────────────────────────┬──────────────────────────────────────────┘
                                    │ USB-TTL 115200 8N1（AA 55 ... CRC16）
┌───────────────────────────────────▼──────────────────────────────────────────┐
│                            STM32F103C8T6 固件                                  │
│                                                                               │
│  ┌── 应用层 App/ ──────────────────────────────────────────────────────────┐  │
│  │  control.c   四状态机 + 安全联锁 + 风扇迟滞（500ms 周期）                │  │
│  │  menu.c      按键菜单：启停/设温/改 PID/保存                             │  │
│  │  comm.c      帧解析状态机 + 命令分发 + 200ms 状态上报                    │  │
│  │  flash_param.c  末页 Flash 读写（关中断临界区 + 回读校验）               │  │
│  │  param_codec.c  镜像序列化 / CRC32（纯 C，可宿主机测试）                 │  │
│  │  pid.c       位置式 PID（纯 C，零 HAL 依赖）                             │  │
│  └───────────────────────────────┬─────────────────────────────────────────┘  │
│                                  │ 只调 Hardware 接口，不碰寄存器              │
│  ┌── 硬件抽象层 Hardware/ ───────▼─────────────────────────────────────────┐  │
│  │  sensor.c  NTC(ADC1_IN0) + 一阶惯性模拟双底层，统一 Sensor_Read()        │  │
│  │  heater.c  TIM1_CH1 1kHz PWM，占空比 0~100                                │  │
│  │  fan.c     PB0 开关（预留 TIM3_CH3 调速）                                 │  │
│  │  key.c     PB12/13/14 状态机消抖（10ms 节拍，无 Delay）                   │  │
│  │  oled.c    SSD1306 软件 I2C（PB6/PB7）                                    │  │
│  └───────────────────────────────┬─────────────────────────────────────────┘  │
│                                  │ HAL API                                    │
│  ┌── 外设层 Core/ ───────────────▼─────────────────────────────────────────┐  │
│  │  adc.c · tim.c · usart.c · gpio.c · stm32f1xx_hal_msp.c · it.c            │  │
│  └─────────────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────────────┘
        │                    │                    │                  │
   PA8 → MOSFET → 加热器   PB0 → MOSFET → 风扇  ADC1_IN0 ← NTC分压  PA9/PA10 USB-TTL
```

依赖方向严格单向：`main → App → Hardware → HAL`。`pid.c` 与 `param_codec.c` 不依赖任何一层，因此可在 PC 上直接编译测试。

## 2. 时间片调度（非阻塞，全部基于 `HAL_GetTick()`）

| 周期 | 任务 | 说明 |
|------|------|------|
| 10 ms | `Key_Scan()` | 3 键并行状态机消抖（20ms 判定、1s 长按） |
| 10 ms | `Menu_Tick()` | 消费按键事件，调控制接口 |
| 10 ms | `Comm_Tick()` | 最多消化 64 字节；每 200ms 主动上报状态帧 |
| 500 ms | `Control_Tick()` | 读传感器 → 联锁 → PID → 风扇迟滞 |
| 500 ms | `Menu_Render()` | OLED 整屏刷新（4 行 16 列） |
| 1000 ms | 秒计数 | 仅用于显示运行时长 |

全工程主循环无 `HAL_Delay`；唯一阻塞点是 OLED 初始化延时（100ms）与 UART 单帧发送（≤3.5ms）。

## 3. 控制数据流

```
        ┌──────────────┐
        │ Sensor_Read()│ ── 10ms? 否：500ms 调用一次
        └──────┬───────┘
               │ Sensor_Data_t {temp, humidity, is_simulated, is_valid}
               ▼
    ┌──────────────────────┐   无效/超 75℃   ┌───────────────────────┐
    │ safety_interlock()   │ ──────────────> │ FAULT：加热 0%，风扇 ON │
    │ 每 tick 最先执行      │                 │ 仅人工确认可解除        │
    └──────┬───────────────┘                 └───────────────────────┘
           │ 正常
           ▼
    ┌──────────────────────┐   duty(0~100)
    │ pid_update(sp, temp) │ ─────────────> Heater_SetDuty() → TIM1 CCR1
    └──────┬───────────────┘
           │ temp 与 target 比较（迟滞）
           ▼
    Fan_On() / Fan_Off()   （> target+2.0℃ 开，< target+0.5℃ 关）
```

状态机：

```
  INIT ──自检通过──> STANDBY ──Control_Start()──> RUNNING
    │                  ▲   │                        │
    │ 传感器无效        │   └────Control_Stop()──────┘
    └──────────────────┼──> FAULT（锁定）
                       └── Control_AckFault()
```

## 4. 关键设计决策

| 决策 | 原因 | 代价 |
|------|------|------|
| PID 纯 C 无 HAL | 可在 PC 上跑真实单测（本项目 20 项用例全过），换 MCU 不用改 | 需要自己传 dt、自己做限幅 |
| 传感器双底层 + `is_simulated` 标志 | 无硬件也能验证完整闭环；SIM/REAL 在 OLED 与上位机双处显式标注，不伪装 | 显示与通信层都要透传该标志 |
| OLED 用软件 I2C（PB6/PB7） | 复用课程里已验证的驱动；不与任何外设抢时序；NTC 方案无需 I2C 外设 | CPU 占用略高（单帧刷新 ~10ms，500ms 一次可忽略） |
| 参数存末页 Flash（0x0800FC00） | C8T6 无 EEPROM；末页不与代码冲突（当前 Code 17KB / 64KB） | 写入需整页擦除，寿命 ~10k 次，所以只在用户显式保存时写 |
| 状态帧 200ms 主动上报 | 上位机无需轮询即可绘图，协议更简单 | 占用约 2.5KB/s 带宽，115200 下充裕 |
| 联锁放在 PID 之前 | 安全优先于控制，任何异常都不允许进入 PID 计算 | 故障时 PID 状态被冻结（下次启动会 reset） |
