## 2. STAR 叙述（面试口述版，约 90 秒）

**S 背景**：想做一个能体现"控制算法 + 嵌入式工程化"的项目，而不是只会点灯的例程拼装。目标是小封闭箱温度闭环，要求安全、可测试、可复现。

**T 任务**：用现有 F103C8T6 + OLED 器件完成闭环控温，同时必须解决两个现实问题：传感器型号不确定、加热器不能上电乱接。

**A 行动**：
1. 把传感器做成双底层——NTC（ADC1_IN0 + Beta 公式）作为真实通道，另写一阶惯性软件模型作为模拟源，统一 `Sensor_Read()` 接口并携带 `is_simulated` 标志；OLED 与上位机都强制显示 SIM/REAL，绝不混用。
2. PID 写成不依赖 HAL 的纯 C 模块，宿主机直接编译实测 20 项用例，覆盖限幅、抗饱和、NaN 拦截；控制周期固定 500ms，输入异常不污染积分状态。
3. 安全做成三层：硬件栅极下拉（上电即关断）→ 软件联锁（失效/超温立即关加热、开风扇、锁定 FAULT）→ 独立温控开关（KZ 继电器/常闭温度开关串联，Firmware 跑飞也能断电）。
4. 通信自己定协议：AA55 + CRC16，非阻塞解析状态机 + 中断环形缓冲，200ms 主动上报；Python 端做协议库 + GUI + 46 项自动化测试。

**R 结果**：全工程 0 Error 0 Warning（Code 17KB），宿主机 87 项测试全过；无硬件时也能完整演示闭环收敛（稳态误差 0.005℃、零超调），有硬件时同一套代码直接跑真实传感器。

## 3. 高频面试问答

### Q1：为什么选位置式 PID 而不是增量式？
位置式直接给出绝对占空比，与"加热功率 0~100%"物理量一一对应，断电/重启后输出可预期；增量式对积分饱和、执行器故障的容错更麻烦，且需要维护上一次输出。我的场景只有一路加热、采样周期固定 500ms，位置式更直观。增量式的好处是天然抗积分饱和和无扰切换，如果做多路或需要频繁手自动切换我会选增量式。

### Q2：积分饱和是怎么产生的？你怎么解决？
执行器饱和（PWM 已经 100%）但误差仍然很大时，积分项继续累加，导致误差反向后输出仍长时间停留在饱和区。我用两层：① 条件积分——输出已饱和且误差仍在向饱和方向推进时冻结积分；② 积分硬限幅（±100）兜底，防参数被改坏时发散。单测里专门验证：饱和 2000 个周期后积分仍为 0，误差反向后 1 个周期即退饱和。

### Q3：控制周期为什么定 500ms？
被控对象是小型封闭箱，热时间常数几十秒量级，500ms 采样远快于对象动态，PID 离散化误差可忽略；同时给按键、串口、OLED 留足 CPU 余量。如果换成加热丝直接贴传感器（秒级时间常数），我会把周期降到 50~100ms 并重新整定微分项。

### Q4：你的 PID 微分项怎么处理噪声？
当前用后向差分 `(e[k]-e[k-1])/Ts`，Kd 取 1.5 比较小，且温度本身经过 8 次 ADC 平均，噪声影响有限。工程上更稳的做法是：微分作用在测量值上（避免设定值阶跃时的微分冲击）+ 一阶低通滤波（不完全微分）。这是我下一步的优化点，代码里已经把 Kd 做成可在线调整，方便对比。

### Q5：温度采样精度怎么保证？
三层：① PA0 模拟输入，采样时间 55.5 周期（源阻抗不高，兼顾速度与精度）；② 8 次采样平均；③ F1 的 ADC 上电做 `HAL_ADCEx_Calibration_Start` 自校准。另外 NTC 用 Beta 公式换算，分压电阻选 10k 与 NTC 标称值匹配，使工作点附近灵敏度最高。当前不足：NTC 的 B 值和实际阻值没做两点校准，绝对精度只能到 ±2℃ 量级——这个我在文档里明确标注了，不吹成"高精度"。

### Q6：传感器坏了系统会怎样？
`Sensor_Read()` 返回 `is_valid=0`：控制层在**每个周期最开始**做联锁判断，直接关加热（PWM 写 0）、开风扇、进 FAULT 并锁定，只能人工确认解除。另外上电自检时如果 PA0 贴轨（开路/短路），系统不会假装有数据，而是切到模拟模式并在 OLED/上位机显示 `SIM`。

### Q7：SIM 模式会不会泄露到生产？怎么保证不混淆？
`is_simulated` 是数据结构里的显式字段，从驱动层一路透传到 OLED 第一行和状态帧第 11 字节，上位机界面用橙色 `SIM` 徽标常驻显示。这是设计约束（约束 3），代码评审和我自己的测试都按"模拟数据不得伪装成实测"检查。

### Q8：为什么用软件 I2C 驱动 OLED 而不是硬件 I2C？
OLED 是唯一的 I2C 器件，速率要求低（500ms 刷一次），软件 I2C 引脚可任意指定，不会和 TIM/UART 抢资源，也便于沿用已经验证过的驱动逻辑。如果后面加 I2C 传感器共享总线，我会切到硬件 I2C1（PB6/PB7 引脚已经预留在方案里）。

### Q9：Flash 参数存储有什么坑？
① C8T6 没有 EEPROM，只能用 Flash，擦除粒度是整页 1KB，所以整页擦+重写；② 擦写期间 CPU 取指停顿，必须关中断（我保存 PRIMASK 后恢复，不用无脑 `__enable_irq`）；③ 写入寿命约 1 万次，所以只在用户长按保存/上位机命令时写，不做定时写；④ 必须有校验——魔数 + 版本 + CRC32，校验失败回默认值并置标志，避免用脏参数去跑 PID。

### Q10：状态机为什么单独一层？直接 if-else 不行吗？
状态机的价值是"非法转移不可能发生"：STANDBY 才能 Start、RUNNING 才能 Stop、FAULT 只能由 ACK 解除且回 STANDBY 不自动恢复。if-else 一旦加功能就容易漏分支。我把它做成 `switch(state)` 单入口，每个 tick 只走一条路径，联锁判断放在 switch 之前，保证安全优先级高于一切业务逻辑。

### Q11：串口接收为什么用环形缓冲 + 状态机，而不是一次收一帧？
中断里只搬 1 字节立刻退出，避免在中断里做 CRC 和业务；解析放主循环 10ms 时间片，最多消化 64 字节，保证不会因为数据量大把控制周期拖慢。缓冲满会丢字节并计数（`Usart_OverflowCount`），可诊断而不是静默出错。

### Q12：协议为什么加 CRC16，不做重传？
CRC16-CCITT 对短帧（≤32 字节）漏检率足够低；重传会引入时延和状态机的复杂度。我的分工是：下位机校验失败就丢帧并回 NACK，上位机负责 300ms 超时重发（GUI/CLI 都可扩展），职责清晰。

### Q13：怎么保证"上电默认关闭"？
三层：① 硬件上栅极有 10k 下拉，复位期间 GPIO 浮空时 MOS 保持关断；② 固件在 `MX_GPIO_Init` 里**先写低电平再配置成输出**；③ TIM1 的 CCR1 初始化为 0、空闲态设 RESET。真实负载接入前还必须用 LED 假负载验证波形。

### Q14：怎么验证 PID 是对的？总不能靠盯着温度看。
把 PID 抽成零依赖的纯 C 模块，在 PC 上用 MSVC 编译，直接 `#include pid.c` 测真实逻辑（不是复制一份），配合一阶惯性对象模型跑四类用例：阶跃响应、输出限幅、积分抗饱和、异常输入。结果写进文档，可复现（`tests/run_tests.bat`）。这套测试在我改参数、改结构时会先跑一遍，属于回归测试。

### Q15：为什么单测能跑在 PC 上，靠的是什么设计？
依赖倒置：`pid.c` 不 include 任何 HAL 头，输入输出全是 float；`param_codec.c` 只操作字节数组。凡是与寄存器打交道的（ADC、TIM、Flash）都放在别的文件。这是分层带来的直接收益——如果 PID 里写了 `HAL_GetTick()`，就只能在板子上调，效率低得多。

### Q16：如果按键抖动导致误触发启动怎么办？
按键用 10ms 节拍的状态机消抖（连续 2 拍稳定才认），短按在**松手**时才产生事件，长按满 1s 才触发且只触发一次；此外启动只是进 RUNNING，联锁仍然每周期生效，误启动不会绕过安全逻辑。物理上还可以加 100nF 电容。

### Q17：中断优先级怎么分配？
SysTick（HAL 时基）最高，USART1 最低（3），因为通信可以等，控制节拍和安全判断不能等。所有耗时逻辑都不在中断里做——中断只搬数据。

### Q18：这个项目最难的地方？
不是 PID 本身，而是"没有硬件也要能验证"。我为此做了双底层传感器、模拟被控对象、宿主机单测、协议测试四件事，让 90% 的逻辑在没有板子时就能验证；剩下 10% 的硬件相关部分，我明确列了待测试清单，而不是写在简历里说"已完成"。

### Q19：如果让你继续优化，下一步做什么？
① NTC 两点校准（0℃ 冰水 + 常温）把绝对精度做到 ±0.5℃；② 微分项加不完全微分与测量值微分，抑制设定值阶跃冲击；③ 风扇从开关升级为 TIM3_CH3 PWM 调速，做温升速率前馈；④ 加看门狗与掉电检测；⑤ 上位机加数据 CSV 导出与参数整定助手（阶跃响应自动算 Kp/Ki）。
